# Development save policy amendment

User instruction, 2026-09-08:

> don't care about preserve existing saves, the game still in development so we don't care

This instruction supersedes R6's backward-compatibility and migration requirements in the original initiative packet and all derived plans/contracts. Existing development saves may become incompatible. No further legacy-save migration, historical registry migration, old-slot preservation fixtures, or compatibility-only release gates are required for this initiative.

Root may change saved structures, version markers and development identity allocations when needed for the complete region, without building a migration for existing saves. Current-format integrity, valid references and protocol agreement still matter. New games must save and reload correctly; party, inventory and regional progress must survive ordinary travel between Johto and Kanto within the current game. One-time rewards, co-op consistency and corruption detection remain functional requirements.

Retain working foundations already implemented unless changing them helps delivery; do not spend time removing compatibility code merely because it is no longer required. Tests should focus on the current build and new saves. This amendment does not authorize deleting user save files, overwriting unrelated source changes, remote publication, deployment or production mutation.

The original approved packet and its receipt remain historical evidence. This explicit user amendment governs future work without another approval step. The existing active goal's older wording about preserving saves is superseded by this instruction. All other full-region requirements and the single final release phase remain in effect.
